## Макет: телефон (`WorksMobile`, &lt; 768px)

```
┌─────────────────────────────────┐
│  Смены          Сентябрь        │  ← свёрнут календарь: месяц по центру шапки
│  Месяц  [‹ Сегодня ›]           │  ← только если месяц открыт
│  Пн … Вс                        │  ← шапка, не в списке
│  неделя  ИЛИ  сетка месяца      │
│  [ полоска свернуть/открыть ]   │
├─────────────────────────────────┤
│  [ Открыть смену ]              │  ← если can("works","create")
│  карточки смен выбранного дня   │  ← свой скролл
└─────────────────────────────────┘
```

Боковое меню на телефоне: внизу имя и переход в профиль. Кнопки выхода в меню нет.

Календарь — часть шапки (как идея ExpandableCalendar): список **не** едет под сетку месяца.

| Состояние | Что видно | Стрелки | Как переключить |
| --- | --- | --- | --- |
| Открыт (старт) | месяц целиком, название, «Сегодня», стрелки | соседний месяц, день = `defaultDayInMonth` | полоска; свайп вверх по календарю (≥ 36 px); прокрутка списка &gt; 8 px |
| Закрыт | одна неделя выбранного дня, дни недели, полоска | нет | тап по числу выбирает день; свайп влево/вправо — соседняя неделя (≥ 36 px); полоска; свайп вниз — открыть месяц |

- Дни со сменами — точка. В свёрнутой неделе выбранный день — круглая обводка. В сетке месяца — обводка `ring-inset` с `--cell-radius`. Подписи **Сб** и **Вс** красные (`text-destructive`), числа без окраски.
- В свёрнутом виде нет названия месяца, «Сегодня» и стрелок — только дни недели, неделя и полоска. В шапке слева «Смены», по центру название месяца.
- Анимация высоты — один Collapsible у сетки месяца (`--collapsible-panel-height`, 500 ms). Неделя лежит в той же ячейке сетки под месяцем, высоты не складываются. На iPhone во время прокрутки списка Safari часто **не играет** CSS-анимацию (скачок). Полоска и свайп по календарю анимируют. При «Уменьшение движения» переход отключён (`motion-reduce:transition-none`).
- Карточка в списке: объект, кто открыл, число людей, сумма, бейдж статуса. Клик открывает полный экран смены (`WorkDetailsMobile`).
- Данные месяца: `useMonthWorks(visibleMonth, undefined, true)` — все смены компании по RLS, без фильтра «Мои».
- Сводки месяца на телефоне нет.

### Карточка смены на телефоне

Клик по смене дня (или сразу после открытия новой смены) заменяет календарь и список полным экраном. Кнопка «Назад» смену **не закрывает**.

```
┌─────────────────────────────────┐
│  [←] Смена <дата>               │
│  статус · объект                │
│  [ Обзор | Работы | Люди ]      │
│  поиск / «+»  (на вкладках)     │
├─────────────────────────────────┤
│  содержимое вкладки             │  ← свой скролл
│  на «Люди»: пресеты 8/10/12     │  ← не в списке, у низа экрана
└─────────────────────────────────┘
```

Те же вкладки и правила правки, что на компьютере (на телефоне вкладки короче: «Обзор», «Работы», «Люди»). Работы и сотрудники — карточки, не таблица.

- **Работы:** «+» и свайп вправо открывают то же мобильное окно снизу, что и открытие смены (`WorkItemAddSheet`): крестик, заголовок, галочка. Свайп влево — удаление.
- **Люди:** «+» и свайп вправо — то же окно (`WorkHourFormSheet`). Свайп влево — удаление. Пресеты и кнопка «Часы» / «Сохранить» — полоса внизу экрана; список над ней.

## Что умеет

Ниже — возможности **компьютера**, если не сказано иное. Телефон: календарь, список дня, открытие смены, полный экран карточки смены (без сводки месяца). На телефоне работы и люди — карточки; добавление работ и часов — панели снизу; пресеты часов — полоса внизу вкладки «Люди».

### Календарь и список слева

- **Календарь месяца.** Стрелки — соседний месяц, кнопка **«Сегодня»** — текущая дата.
- Дни со сменами отмечены точкой. Выбранный день обведён рамкой. Дни соседних месяцев не показываются.
- Клик по дню показывает смены **этого дня** и сводку **этого месяца** справа.
- Клик по смене открывает карточку справа. Повторный клик снимает выделение.
- Слева над списком смен дня — кнопка **«Открыть смену»** (если есть право `works.create`).
- При первой загрузке открыт текущий месяц и сегодняшняя дата.
- Показаны все смены компании (по доступным объектам). Отдельного фильтра «Мои» нет.

### Сводка месяца (правая колонка)

Отображается, когда месяц выбран (раскрыт или активен по умолчанию) и смена не открыта — либо когда выбрана смена, но активен режим «Сводка».

1. **Шапка месяца** — название, бейдж «Текущий месяц», число смен. При фильтре по объекту — плашка с названием площадки и кнопка сброса.
2. **Финансовый блок** — общий объём, «своими силами», субподряд; проценты и полоса распределения; средняя ставка ₽/час.
3. **График «Динамика выработки»** — столбцы по дням месяца. Подсказка при наведении: дата, сумма, разбивка свои/подряд, число смен и специалистов, объекты. Отмечены пик месяца, среднее за день и текущий день.
4. **KPI-плитки** — всего смен (закрытые / открытые), часов, специалистов, средняя смена и выработка на человека.
5. **По объектам** — рейтинг с долей в % и фоновой полосой. Клик по объекту фильтрует сводку (график, KPI, системы). Список смен слева **не** меняется.
6. **По системам** — топ-5 с кнопкой «Показать все». Учитывает фильтр по объекту, если он включён.

### Карточка смены (правая колонка)

Открывается при клике на смену. Шапка, вкладки и поиск — **один блок**. Ниже скроллится содержимое вкладки.

| Вкладка | Компьютер | Телефон |
| --- | --- | --- |
| **Обзор и фото** / **Обзор** | Чеклист и закрытие, KPI, «Кто выполнил», фото | То же |
| **Работы** | Таблица | Карточки |
| **Сотрудники** / **Люди** | Таблица | Карточки + панель пресетов внизу |

На вкладках «Работы» и «Сотрудники» в заголовке вкладки показан счётчик позиций/людей из полей смены.

### Переключение «Сводка ↔ Смена»

Если смена выбрана, над контентом появляется панель:

- **Сводка за &lt;месяц&gt;** — вернуться к месячной аналитике (смена остаётся выделенной в списке).
- **Смена: &lt;дата&gt;** — открыть детали выбранной смены.
- **Скрыть** — снять выделение и вернуться к сводке (смена в базе не закрывается).

## Открытие смены

Как в приложении. Смена всегда на **сегодня**. Форма одна: `WorkOpenForm`.

| Где | Оболочка |
| --- | --- |
| Компьютер | `WorkOpenDialog` — окно по центру |
| Телефон | `WorkOpenSheet` — панель снизу по высоте содержимого (не выше `100dvh − 4.5rem`): полоска, крестик слева, заголовок по центру. Справа галочка, пока форма не заполнена; когда всё готово — кнопка «Открыть». Если список длинный — крутится внутри окна |

Фото: `input type="file" accept="image/*"` **без** `capture` — система предлагает камеру или галерею.

1. Если у текущего пользователя уже есть смена со статусом `open` в этой компании — новую открыть нельзя (проверка до окна и ещё раз в `openWork`).
2. Объект — только из `profiles.object_ids` **и только со статусом «Активный»**. Приостановленные и завершённые не показываются. Если активный объект один, он подставляется сам.
3. Сотрудники — статус «Работает», привязаны к выбранному объекту, ещё не стоят в чужой **открытой** смене на сегодня. Нужен хотя бы один человек. На телефоне в списке только ФИО, без должности; видно до 10 строк, остальные — прокрутка списка.
4. Утреннее фото обязательно, до **4** снимков. Одно фото уходит как есть; 2–4 собираются на устройстве в один JPEG-коллаж и пишутся в `works.photo_url`. Сжатие (длинная сторона до 1600 px). Bucket `works`, путь `{objectId}/{дд-мм-гггг}/{гггг-мм-дд_чч-мм-сс}_morning.jpg`. Нажатие на кадр — просмотр, замена или удаление этого кадра.
5. В базу пишется строка `works` (`status = open`, `opened_by` = текущий пользователь, `photo_url`). Id смены задаёт база.
6. Выбранные люди — строки `work_hours` с часами 0. Id часов — `createId()` (`src/lib/utils/create-id.ts`): `crypto.randomUUID`, если есть; иначе UUID v4 через `crypto.getRandomValues`. На телефоне по `http://192.168…` `randomUUID` нет.
7. Затем RPC `enqueue_telegram_outbox_opening` и вызов `process_telegram_outbox`; push админам — функция `send_admin_work_event` с `action: open`. Ошибки Telegram и push смену не откатывают.
8. Напоминания на телефон из веба не ставятся.
9. Кэш: `invalidateQueries(["works"])`.

После успеха:

- **Компьютер:** выбран день новой смены, справа открывается её карточка.
- **Телефон:** выбран день новой смены, календарь сворачивается в неделю, сразу открывается карточка этой смены.

## Закрытие смены

Как в приложении (блок проверки на вкладке обзора). Кнопка **«Скрыть»** в шапке карточки **не закрывает** смену — только убирает карточку.

На вкладке **«Обзор и фото»**, пока смена открыта:

1. Пока условия не выполнены — красный чеклист: работы, сотрудники, количества > 0, часы > 0, вечернее фото.
2. Вечернее фото — кнопка **«Добавить фото»**. Файл в bucket `works`, путь `{objectId}/{дд-мм-гггг}/{время}_evening.jpg`, затем поле `works.evening_photo_url`.
3. Когда всё готово — кнопка **«Закрыть смену»** и подтверждение. После закрытия работы, часы и фото этой смены в вебе менять нельзя (кроме супер-админа).
4. В базу пишется `status = closed`. Telegram закрытия ставит триггер базы; веб вызывает `process_telegram_outbox` и `send_admin_work_event` с `action: close`. Ошибки уведомлений закрытие не откатывают.

Закрыть может тот же, кто может менять работы этой смены: открытую — кто открыл, закрытую править в вебе может только супер-админ.

### Супер-админ: снова открыть и удалить

Только роль **«Супер-админ»**. В шапке карточки — **«Удалить»** (открытую и закрытую). На вкладке обзора у закрытой смены — **«Открыть смену»** (статус снова `open`). Работы и часы удаляются вместе со сменой. Уведомления в Telegram при повторном открытии не отправляются.

В базе функция `check_work_editable` для супер-админа разрешает правку и удаление закрытых смен (как для владельца компании).

## Вкладка «Работы»

Таблица: №, наименование (под ним система · участок · этаж), кол-во, единица, сумма, исполнитель. **Подсистема в таблице не показывается.** Шапка закреплена при прокрутке, внизу — итог по видимым строкам. На телефоне карточка: номер; наименование слева, количество и единица справа; ниже место и исполнитель, сумма справа.

В шапке карточки на этой вкладке:

- фильтры **система / участок / этаж** (без подписей, в списках есть «Все …»);
- поиск по наименованию и связанным полям;
- кнопка **«+»**, если есть право на правку.

### Что можно сделать со строкой

| Действие | Компьютер | Телефон | Ограничения |
| --- | --- | --- | --- |
| Количество | Клик по числу в колонке | Клик по числу на карточке | Те же права; позиция не в акте |
| Изменить | Карандаш | свайп **вправо** | Позиция не в акте |
| Удалить | Корзина, затем подтверждение | свайп **влево**, затем подтверждение | Позиция не в акте |
| Добавить | «+» | «+» | Несколько позиций сметы сразу |

Строка с `contract_act_id` (уже в акте): правка и удаление недоступны, под наименованием текст «В акте, правка недоступна».

### Окно «Добавить работы» / «Изменить работу»

Одна форма. Заголовок и кнопка сохранения зависят от режима («Добавить» или «Сохранить»).

Порядок полей (следующее открывается после предыдущего):

1. **Система** — из сметы объекта (`visible_in_estimates_module`).
2. **Подсистема** — после системы, из той же сметы.
3. **Участок** — после подсистемы. Можно выбрать из списка (уже использованные на объекте + в этой смене) или **ввести свой**.
4. **Этаж** — после участка. Тоже список или свой текст.
5. **Подрядчик** — «Свои» или контрагент.

Дальше поиск по смете и список позиций. Пока не заполнены система, подсистема, участок и этаж, список не показывается.

- **Добавление:** несколько галочек, у каждой выбранной — количество.
- **Правка:** одна позиция (точка), количество в той же строке.
- **Новый материал** (только добавление, не правка): если позиции нет в списке, кнопка открывает ту же логику, что в приложении. Пишется строка в смету объекта (система и подсистема уже выбранные, количество и цена 0, номер `д-N`), затем строка отмечается в списке смены. На компьютере поля сменяют содержимое окна по центру; на телефоне — ту же панель снизу, крестик возвращает к списку сметы.
- Позиция сметы, которая уже есть в смене на том же участке, этаже, системе, подсистеме и подрядчике, в списке скрыта (текущая строка при правке не скрывается).
- Кнопки **«Отмена»** и **«Добавить» / «Сохранить»** закреплены внизу. Прокручивается только список позиций.
- На компьютере — окно по центру: фильтры и список вместе. На телефоне — шапка как у открытия смены. Сначала окно по высоте полей. Когда появляется список сметы, окно растёт; если список длинный — до почти всего экрана, крутится только список.

После записи итоги смены пересчитывает база (`update_work_aggregates`). Список смен слева подхватывает новые суммы после обновления кэша.

## Вкладка «Сотрудники»

Таблица: сотрудник (фото и ФИО), должность, часы, комментарий. Поиск в шапке фильтрует по ФИО, должности и комментарию. На телефоне — карточка: ФИО, часы, комментарий; без фото и должности.

В шапке на этой вкладке — поиск и кнопка **«+»**, если есть право на правку (те же правила, что у работ).

Кнопки **8 / 10 / 12 ч** («Всем») проставляют часы **всем** в смене (не только видимым по поиску) и открывают правку списка. **«Часы»** открывает поля без пресета. **«Сохранить»** пишет изменённые строки одним запросом (`update-work-hours-bulk.ts`). Пустое поле строку не меняет. Некорректное число блокирует сохранение. Комментарий — карандаш / свайп.

| Где | Пресеты и сохранение | Поля часов |
| --- | --- | --- |
| Компьютер | Над таблицей | Колонка «Часы» |
| Телефон | Полоса у низа экрана, список крутится выше | Поле на карточке |

### Что можно сделать со строкой

| Действие | Компьютер | Телефон |
| --- | --- | --- |
| Добавить | «+», окно по центру | «+», панель снизу |
| Изменить карточку (часы и комментарий) | Карандаш, окно по центру | свайп **вправо**, панель снизу |
| Удалить | Корзина, затем подтверждение | свайп **влево**, затем подтверждение |
| Часы всем / в списке | «Всем 8/10/12», «Часы», «Сохранить» | то же, панель внизу экрана |

В список добавления попадают только сотрудники со статусом **«Работает»**, привязанные к **объекту этой смены**, которых ещё нет в смене. Часы можно не заполнять — как в приложении.

Счётчик людей на вкладке и в сводке смены берётся из `works.employees_count` (пересчитывает база).

## Правила

- Видны только смены **активной компании** и только по **доступным объектам** (RLS в базе).
- Итоги месяца считает **сервер** теми же RPC, что и приложение.
- Номер позиции в работах берётся из сметы (`estimates.number` через JOIN), в `work_items` не хранится.
- Сумма «своими силами» в карточке смены — позиции **без** `contractor_id`. Общая сумма смены — из полей `works.total_amount` / `own_total_amount`.
- Фильтр по объекту в сводке влияет только на правую панель; левый список смен не пересчитывается.
- Смена месяца (стрелки календаря / «Сегодня») сбрасывает выбранную смену и фильтр объекта.
- Сумму строки считает клиент как цена × количество (как в приложении). Итоги смены пересчитывает база.

### Кто может менять работы в вебе

Проверка в кнопках (`canModifyWorkItems`) и ещё раз перед записью (`assertCanWriteWorkItems`). Нужно право модуля `works.update`.

| Смена | Кто может менять работы |
| --- | --- |
| Открыта (`open`) | Только тот, кто её открыл (`opened_by`) |
| Закрыта (`closed`) | Только роль **«Супер-админ»** (`is_super_admin`) |

**Владелец компании этого права не даёт.** В приложении владелец по-прежнему может править закрытую смену долгим нажатием: политики RLS в базе под веб не ужесточались, чтобы это не сломать.

Роль «Супер-админ» — системная роль в таблице `roles` (`role_name`, `is_system`). Если она никому не назначена, закрытые смены в вебе править нельзя.

## Пока нет

Это есть в приложении, в вебе пока нет:

- планы работ (список, создание, правка, удаление)
- фильтр «Все / Мои смены»
- список смен группой по месяцам (в вебе календарь одного месяца)
- сводка месяца на телефоне
- прямая ссылка на смену (`/works/…id`)
- замена утреннего фото после открытия и замена вечернего из просмотра
- поле «число специалистов» у подрядчика в форме работ
- блок «распределение работ по системам» в обзоре смены
- владелец компании правит закрытую смену и удаляет любую (в вебе только супер-админ)
- напоминания на телефон после открытия смены

Выгрузка поиска работ в Excel в вебе — отдельный экран [Журнал работ](./work-journal.md) (в приложении модуль «Выгрузка»).

## База данных

### Таблицы

| Таблица | Назначение | Веб пишет |
| --- | --- | --- |
| `works` | Смены: дата, объект, статус, суммы, фото, счётчики | да: открытие, вечернее фото, закрытие, повторное открытие и удаление (супер-админ) |
| `work_items` | Позиции работ в смене | да: вставка, правка, удаление, количество |
| `work_hours` | Часы сотрудников в смене | да: вставка, правка часов/комментария, массовое обновление часов, удаление |

### Связанные данные (JOIN)

| Таблица | Поле | Для чего |
| --- | --- | --- |
| `objects` | `object_id` | Название объекта |
| `profiles` | `opened_by` | Кто открыл смену |
| `estimates` | `estimate_id` | Номер, имя, единица, цена позиции сметы |
| `contractors` | `contractor_id` | Имя подрядчика |
| `employees` | `employee_id` | ФИО, должность, фото в табеле |

### RPC

| Функция | Параметры | Что возвращает |
| --- | --- | --- |
| `get_months_summary` | `p_company_id`, `p_opened_by?` | Заголовки месяцев: число смен, суммы |
| `get_month_objects_summary` | `p_month`, `p_company_id` | Объекты: смены, суммы |
| `get_month_systems_summary` | `p_month`, `p_company_id`, `p_object_id?` | Системы: позиции, суммы |
| `get_month_hours_summary` | `p_month`, `p_company_id`, `p_object_id?` | Суммарные часы |
| `get_month_employees_summary` | `p_month`, `p_company_id`, `p_object_id?` | Число выходов в смены: `COUNT(work_hours.employee_id)`, не уникальные люди |
| `get_object_sections` | `target_object_id`, `p_company_id` | Участки, уже встречавшиеся на объекте |
| `get_object_floors` | `target_object_id`, `p_company_id` | Этажи, уже встречавшиеся на объекте |
| `is_super_admin` | `user_id` | Есть ли у пользователя роль «Супер-админ» |

Сметы для выбора позиций: таблица `estimates` объекта, только `visible_in_estimates_module = true`.

### Фото смены

Публичные URL в полях `works.photo_url` (утро) и `works.evening_photo_url` (вечер). Время съёмки извлекается из имени файла в URL (`extractPhotoTime`).
