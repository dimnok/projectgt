## Что это

Диалог с ИИ. Собеседник пока один — помощник. Переписка хранится в базе, поэтому её видно после перезахода с любого устройства: у каждого своя.

**Компьютер:** два столбца — слева диалоги, справа переписка.  
**Телефон:** переписка на весь экран, список диалогов — по кнопке в шапке.  
**Плавающая панель:** та же переписка узким окном, с кнопкой перехода в полный раздел.

## Как отвечает помощник

Серверная функция `gt_chat` берёт переписку из базы, отправляет её модели (шлюз KodikRouter, по умолчанию `deepseek/deepseek-v4.1-flash`) и дописывает ответ в диалог. Ключ модели живёт в секретах функций и в браузер не попадает.

Помощник отвечает простым текстом: перечисления строками («- » или «1) »). Таблицы и выделение звёздочками просить нельзя — чат показывает текст как есть, и разметка была бы видна символами.

## Данные компании

У помощника две функции, обе вызываются от имени человека.

### Смены за сегодня — `get_shift_status_today`

Отвечает на вопросы «кто сегодня на смене», «кто не вышел».

- Объект можно назвать словами («ЦОД Салтыковка»), можно не называть — тогда данные по всей компании. Поиск по части названия работает; если название подходит нескольким объектам, помощник попросит уточнить.
- Статусы: **в открытой смене** — сейчас работает; **закрыл смену** — сегодня уже отработал (закрытая смена или ручная отметка посещаемости); **не вышел** — сегодня не отмечен нигде.
- «Не вышел» = нет открытой смены сегодня — тот же смысл, что у фильтра «не в смене сегодня» в табеле. Отдельный статус «закрыл смену» нужен, чтобы вечером отработавшие не выглядели как не вышедшие.
- Список строится по работающим сотрудникам, закреплённым за объектами. Уволенные и сотрудники без объектов в ответ не попадают.
- «Сегодня» считается по Москве: база живёт в UTC, а смены открываются по местной дате.
- Ответ строится только на данных из базы. Если объект не найден, помощник скажет об этом и предложит уточнить название.

### Часы и посещаемость за месяц — `get_employee_month_summary`

Отвечает на вопросы «сколько отработал Иванов в августе», «сколько часов у …», «посещаемость … за месяц». Нужны ФИО, год и номер месяца.

- ФИО можно называть частично («Иванов»). Если подходит несколько человек — помощник попросит уточнить; если не нашёл — покажет доступных сотрудников.
- Часы: **всего за месяц** = часы закрытых смен + ручные часы посещаемости. Открытые смены в часы не входят — они считаются после закрытия смены. Есть разбивка по объектам.
- Посещаемость: **выходы** — дни с часами (включая выходные, если работали); **будни** — рабочие дни (Пн–Пт) месяца; **пропуски** — будни без часов. Сегодняшний день в пропуски не входит: смена может быть ещё открыта, статус на сегодня отвечает функция смен.
- Ручная отметка с нулём часов выходом не считается.
- «Сегодня» и граница месяца считаются по Москве.

Остальных данных компании (суммы, сметы, зарплаты, остатки) у помощника по-прежнему нет — он не должен их выдумывать. Денег (зарплаты, ставки, суммы) у него тоже нет.

## Поиск в интернете

Помощник **умеет искать в интернете**: к запросу подключается плагин `web` шлюза. Свежие данные (погода, курсы, новости, цены) берутся из найденного, а не из памяти модели; в ответе помощник даёт 1–2 ссылки на источники, и они открываются по нажатию.

Поиск идёт с каждым вопросом — ответ занимает на несколько секунд дольше, и поиск тарифицируется отдельно.

Выключить поиск без правки кода: секрет функций `GT_CHAT_WEB_SEARCH=off`.

Модель можно заменить без правки кода: секрет `GT_CHAT_MODEL` у функций. Нашему ключу доступна одна модель — `deepseek/deepseek-v4.1-flash`; чтобы появились другие, нужно расширить доступ в панели KodikRouter.

## Диалоги

- Название диалога берётся из первого сообщения (первые 60 символов). Пустой диалог называется «Новый диалог».
- Кнопка «Новый диалог» сначала переиспользует пустой диалог, чтобы список не заполнялся пустышками.
- Удаление диалога удаляет и все сообщения. Вернуть нельзя.
- Если помощник не ответил (нет связи или ошибка модели), вопрос остаётся в переписке — под лентой появляется кнопка «Получить ответ».

## Права

Модуль прав — `chat`: просмотр, создание, удаление. Права выданы **всем ролям** миграцией, чтобы раздел не пропал у сотрудников; снять их можно в «Управлении ролями».

Без права «создание» поле ввода скрыто — чат можно только читать.

Ответы про смены и часы требуют ещё и права **«Табель — просмотр»** (`timesheet.read`): без него помощник откажет, даже если чат доступен. Так сотрудник не увидит людей и объекты, которых нет в его табеле. Область объектов та же: владелец компании и супер-админ — вся компания, остальные — только объекты из своего профиля.

## Как выложить

1. Миграции `supabase/migrations/` — `20260918120000_create_gt_chat_module.sql` (таблицы, функции, модуль прав), `20260919150000_gt_chat_shift_status_tool.sql` (данные по сменам) и `20260921150000_gt_chat_employee_month_summary.sql` (часы и посещаемость за месяц).
2. Функция `supabase/functions/gt_chat` — `./scripts/deploy-function.sh gt_chat`.
3. Сайт — `./scripts/push_react_app.sh`.

Проверка миграций без сервера: `./scripts/check-gt-chat-migration.sh`, `./scripts/check-gt-chat-shift-tool-migration.sh` и `./scripts/check-gt-chat-employee-month-migration.sh` (поднимают временную базу Postgres и прогоняют миграцию).

## На будущее

Схема уже сделана как настоящий чат: диалог, участники, сообщения. Чтобы перевести раздел на переписку между людьми, нужно добавить второго участника в `chat_thread_members`, показать его в интерфейсе и включить живую доставку сообщений — таблицы и права переделывать не придётся.

Новые данные помощнику добавляются так же, как смены: функция в базе с проверкой прав и области объектов, описание инструмента в `supabase/functions/gt_chat/index.ts`, затем `./scripts/deploy-function.sh gt_chat`. Разметку ответа менять не нужно.
