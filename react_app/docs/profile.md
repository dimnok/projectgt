# Профиль

**Дата:** 13.09.2026 (обновление 11)  
**Экран:** `/profile` (компьютер и телефон)  
**Данные:** таблица `profiles`, членство в `company_members`, фото в Storage `avatars`, RPC `get_my_profile_finance`

Личный кабинет текущего пользователя. На компьютере открывается из аватара в шапке. На телефоне — из блока с именем внизу бокового меню.

Интерфейс **разный**. Компьютер: визитка и вкладки. Телефон: своя шапка (меню + «Профиль»), круглое фото, имя и одна строка (должность или роль · компания), список разделов. Каждый раздел — отдельный экран с «Назад».

## Что умеет

### Визитка (компьютер)
- Фото: загрузка, просмотр, удаление
- ФИО, статус «Активен», бейджи: роль, компания, должность
- Короткий ID с копированием, дата регистрации

### Шапка (телефон)
- Круглое фото (камера, удаление)
- ФИО
- Одна серая строка: должность (если есть) или роль и название компании
- Значки роли / «Активен» / компания / должность **не** показываются

### Личные данные
- Редактирование ФИО и телефона, маска `+7 900 000 00 00`
- Почта только для чтения (логин)
- Карточка связанного сотрудника только просмотр. Назначает руководитель в [Пользователи](./users.md)

### Финансы
Только свой сотрудник и активная компания (`profiles.employee_id` + `last_company_id`). Нет карточки — пояснение, без чужих цифр.

**Сводка выбранного месяца** (будущие месяцы закрыты):

| Строка | Смысл |
| --- | --- |
| По ставке | Часы закрытых смен и табеля × ставка дня |
| Суточные | Как в ФОТ (именная ставка объекта важнее общей) |
| Премии | Сумма за **этот месяц** |
| Штрафы | Сумма за **этот месяц** |
| Итого к оплате | ставка + суточные + премии − штрафы за месяц |

Выплаты **не входят** в сводку месяца: у перевода есть только дата, не «за какой месяц».

**Списки внизу (за всё время):**

- Часы — только выбранный месяц, по дням
- Премии — все записи сотрудника
- Штрафы — все записи сотрудника
- Выплаты — все свои переводы; дата = когда ушли деньги

Остаток за всё время: все начисления минус все выплаты (`calculate_single_employee_balance`). Мелкой строкой.

**Компьютер:** таблица сводки месяца; вкладки детализации: часы, премии, штрафы, выплаты.  
**Телефон:** те же пять строк месяца; ниже отдельная строка «Выплаты»; списки на отдельных экранах.

**Сервер:** `get_my_profile_finance(p_year, p_month)` — SECURITY DEFINER, `search_path = public`, EXECUTE только у `authenticated` (не у `anon`). Клиенту не отдаётся ведомость всей компании. FIFO из ФОТ и из старого экрана Flutter **не используется**.

Миграции: `20260910140000_get_my_profile_finance`, `20260910150000_profile_finance_bonus_penalty_all_time`, `20260910160000_profile_finance_payouts_all_time`.

Канон расчёта часов/ставки/суточных месяца совпадает с `calculate_payroll_for_month` без фильтра объектов. Описание FIFO в ФОТ: [`docs/fot/calculations.md`](../../docs/fot/calculations.md). Экран финансов в приложении: [`docs/FINANCIAL_INFO.md`](../../docs/FINANCIAL_INFO.md) — это Flutter, не веб.

### Уведомления
- Напоминания о сменах: тумблер и до 4 слотов (`profiles.slot_times`)
- Push устройства: статус разрешения в браузере
- Telegram: статус `telegram_user_id`

### Организация и доступ
- Активная компания, роль, переключение при нескольких компаниях
- Блок «Производство»: минимум выработки компании, ₽ / чел. / час (`companies.min_output_per_person_hour`, миграция `20260913100000_companies_min_output_per_person_hour`). Смотрят все участники, меняет только владелец организации. Пустое поле сбрасывает план. Как пунктир считается на [главной](./home.md): часы смен × норма; сплошная линия — факт в ₽
- Список закреплённых объектов

### Настройки и система
- Тема: светлая, тёмная, фирменная
- Версия: крупно номер релиза (`package.json`), мелко дата сборки и короткий код; режим PWA или браузер, онлайн/офлайн
- Если на сервере уже новая сборка — в шапке колокольчик с точкой, в профиле кнопка «Обновить». В окошке колокольчика видно дату и код **новой** сборки — той, что придёт после обновления
- Проверка идёт раз в 2 минуты и при возврате на вкладку. **Код сборки** — отпечаток содержимого сайта: меняется при правках, не меняется при пересборке без правок. Поэтому ложных уведомлений не бывает, а обновление находится всегда. Если хостинг передаёт коммит репозитория сайта — используется он
- Выход с подтверждением

## Правила

- Данные в одной секции, без дублей
- Сам пользователь меняет ФИО, телефон, фото, слоты уведомлений, активную компанию. Норму выработки компании — только владелец. Роль, объекты, привязку к сотруднику — руководитель
- Привязку `profiles.employee_id` меняет право `users.update`. База проверяет триггером
- Телефон на экране: `+7 900 000 00 00`
- Фото: бакет `avatars`, папка `profiles/{id пользователя}`
- Роль из `company_members` активной компании (RBAC v3)
- Финансы: сводка месяца без выплат; списки премий, штрафов и выплат — за всё время
