# ФОТ (фонд оплаты труда)

**Дата:** 19.09.2026  
**Экран:** `/payrolls` — `PayrollsDesktop`. Только компьютер. На телефоне раздел в меню не показывается; адрес переводит на работы или в профиль.  
**Данные:** `payroll_bonus`, `payroll_penalty`, `payroll_payout`, `employee_rates`, `work_hours` + `works`, `employee_attendance`, `business_trip_rates`, `employees`, `objects`. Та же база, что у рабочего приложения. Flutter этим экраном не управляется.  
**Режим:** просмотр, выгрузка в Excel, создание, правка и удаление премий, удержаний и выплат. Дублирование записей, массовые операции и импорт из Excel — следующие шаги.  
**19.09.2026:** добавлены операции — создание премий, удержаний и выплат правым кликом по сотруднику на вкладке ФОТ, правка и удаление записей с отменой, быстрая выплата «по остатку», предупреждение о переплате, история операций сотрудника с итогами за всё время, массовые операции, импорт из Excel с шаблоном, аудит автора и проверка прав `payroll.*` в базе.

## Макет

Одна карточка на весь экран — как в «Сметах»: вкладки, полоса показателей, панель фильтров, таблица.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│          ( ФОТ )  Премии  Удержания  Выплаты                                  │
├──────────────────────────────────────────────────────────────────────────────┤
│ К выплате        │ Выплачено        │ Остаток         │ Баланс                │
│ 12 345 678,90 ₽  │ 11 000 000,00 ₽  │ 1 345 678,90 ₽  │ 456 789,00 ₽          │
├──────────────────────────────────────────────────────────────────────────────┤
│ [<] Сентябрь 2026 [>] │ Всё время │  [Объекты ▾]  [Статус ▾]  [Поиск по ФИО…]  │
├──────────────────────────────────────────────────────────────────────────────┤
│ Сотрудник        │ Часы │ Ставка │ База │ Премии │ … │ К выплате │ Баланс    │
│ Иванов Иван      │ 168  │ 500,00 │ …    │ —      │ … │ 84 000,00 │ 12 000,00 │
├──────────────────────────────────────────────────────────────────────────────┤
│ Итого            │ 168  │        │ …    │ …      │ … │ 84 000,00 │ 12 000,00 │
└──────────────────────────────────────────────────────────────────────────────┘
```

- Вкладки переключают раздел без перезагрузки: полоса вкладок по центру, все вкладки одной ширины. Фильтры периода, поиска и объектов общие для всех вкладок и сохраняются при переходе.
- Полоса показателей и панель фильтров у каждой вкладки свои.
- Колонка «Сотрудник» закреплена слева, шапка и строка «Итого» — сверху и снизу: при горизонтальной прокрутке не теряются.
- Пока идёт фоновый пересчёт, таблица остаётся на экране, справа сверху — пометка «Обновление данных...».

## Вкладки

| Вкладка | Период | Колонки |
| --- | --- | --- |
| **ФОТ** | всегда месяц | Сотрудник · Часы · Ставка · База · Премии · Удержания · Суточные · К выплате · Выплаты · Остаток · Баланс |
| **Премии** | месяц или всё время | Дата · Сотрудник · Сумма (+) · Объект · Примечание · Автор |
| **Удержания** | месяц или всё время | Дата · Сотрудник · Сумма (−) · Объект · Примечание · Автор |
| **Выплаты** | месяц или всё время | Дата · Сотрудник · Сумма · Способ · Тип · Комментарий · Автор |

- Премии и удержания — одна сущность с разным знаком суммы. В приложении вкладка называется «Штрафы»; в вебе — «Удержания», данные те же (`payroll_penalty`).
- У выплат нет объекта, поэтому фильтр «Объекты» на этой вкладке скрыт.
- Порядок — по дате, новые сверху. Длинные примечания, комментарии и названия объектов обрезаются, полный текст — во всплывающей подсказке.
- На вкладке ФОТ **заголовки колонок сортируют таблицу**: клик по сумме — от больших к меньшим, клик по «Сотрудник» — по алфавиту. Второй клик разворачивает порядок, **третий возвращает исходный** (по ФИО). Направление показывает стрелка в заголовке, а подсказка при наведении говорит, что будет по клику. Строка «Итого» считается по всем строкам и от порядка не зависит.
- Клик по ФИО открывает карточку сотрудника (право `employees.read`).
- На вкладках-списках правый клик по записи открывает меню: «Изменить» и «Удалить» (см. «Операции»).

## Операции: премии, удержания и выплаты

Записи заводятся с вкладки **ФОТ** — правым кликом по строке сотрудника. Сотрудник уже выбран строкой: в шапке окна показывается его ФИО, отдельно выбирать не нужно.

Меню по правому клику:

| Пункт | Что открывает | Право |
| --- | --- | --- |
| Начислить премию | Окно премии | `payroll.create` |
| Добавить удержание | Окно удержания | `payroll.create` |
| Сделать выплату | Окно выплаты | `payroll.create` |
| Выплатить остаток | Окно выплаты с суммой, равной долгу | `payroll.create` |
| История операций | Окно истории сотрудника | `payroll.read` |
| Открыть карточку сотрудника | Карточка по ФИО | `employees.read` |

Пункты операций показываются при праве `payroll.create`, «История операций» — всегда (раздел и так под `payroll.read`), карточка — при `employees.read`. «Выплатить остаток» появляется, только если у сотрудника есть долг (положительный баланс).

**Окно премии или удержания** — компактное окно по центру: Дата (по умолчанию сегодня), Сумма (курсор сразу в поле), Объект (обязательный), Примечание (у удержания — «Комментарий»). Пишется в `payroll_bonus` или `payroll_penalty` с `type = 'manual'`.

**Окно выплаты**: Дата (сегодня), Сумма (подставляется «Остаток», если он больше нуля, иначе «Баланс»), Способ (Карта / Наличные / Банковский перевод), Тип (Зарплата / Аванс), Комментарий. Пишется в `payroll_payout`. Если сумма больше долга сотрудника, под полем появляется предупреждение о переплате — сохранить всё равно можно.

**Быстрая выплата.** Пункт «Выплатить остаток» открывает окно выплаты с уже подставленной суммой долга. Обычный пункт «Сделать выплату» подставляет «Остаток» месяца.

**История операций.** Пункт «История операций» открывает широкое окно сотрудника. Сверху — итоги **за всё время**: Заработано (база + суточные + премии − удержания), Суточные, Премии, Удержания, Выплаты, Остаток. Ниже — списки премий, удержаний и выплат с итогами по разделу; переключатель — выбранный месяц или всё время. Правка и удаление операций обновляют историю автоматически.

**Изменение.** На вкладках Премии / Удержания / Выплаты правый клик по записи → «Изменить» (право `payroll.update`) — открывается то же окно, что при создании, с заполненными полями. Сотрудник не меняется. После сохранения в уведомлении есть «Вернуть прежнее».

**Отмена.** После сохранения в уведомлении есть «Отменить» — созданная запись удаляется. После удаления — «Вернуть»: запись создаётся заново с тем же идентификатором.

**Удаление.** На вкладках Премии / Удержания / Выплаты правый клик по записи → «Удалить» (право `payroll.delete`). Удаление подтверждается окном со сводкой записи (дата · сотрудник · сумма).

**Автор.** В списках есть колонка «Автор» — кто создал запись; в подсказке при наведении видно и того, кто изменил. Заполняется автоматически при записи (см. «База»).

**Пересчёт.** После любой операции обновляются ведомость месяца, FIFO выплат и оба списка — цифры на вкладках не расходятся.

- Объект у премии и удержания обязателен: без него запись не попала бы в ведомость при фильтре по объекту.
- История операций — только просмотр; изменять записи можно из списков на вкладках.
- Кнопки «⋯» нет — меню открывается только правым кликом и только на компьютере.

## Массовые операции

На вкладке **ФОТ** можно выделить нескольких сотрудников (галочки в колонке «Сотрудник», кнопка «Выбрать всех») и выполнить операцию сразу для всех:

| Кнопка | Общие поля | Сумма |
| --- | --- | --- |
| Премия | Дата, Объект, Примечание | у каждого своя, кнопка «Заполнить всем» |
| Удержание | Дата, Объект, Комментарий | то же |
| Выплатить | Дата, Способ, Тип, Комментарий | предзаполняется долгом, переплата подсвечивается |

Строки с нулевой суммой пропускаются. Запись идёт **одной вставкой** (либо все строки, либо ни одной); в уведомлении есть «Отменить». Нужно право `payroll.create`.

## Импорт из Excel

Кнопка **«Импорт»** — в панели фильтров вкладок Премии / Удержания / Выплаты (право `payroll.create`).

1. **«Шаблон»** скачивает пустой `.xlsx` с нужными колонками (его отдаёт Node-роут).
2. Выбор файла — разбор идёт на **Node-роуте** `/api/payroll/import/parse`; в базу при разборе ничего не пишется.
3. **Предпросмотр:** ФИО из файла, найденный сотрудник, сумма, дата, объект, примечание. Неоднозначные ФИО выбираются вручную, **ненайденные пропускаются**.
4. **«Сохранить»** — запись из браузера (права и аудит как обычно), в уведомлении «Отменить».

Колонки файла: **ФИО** и **Сумма** обязательны, **Дата**, **Объект** (для премий и удержаний) и **Примечание**/**Комментарий** — по желанию. Если даты или объекта в файле нет, берутся общие значения из окна импорта.

## Период и поиск

- По умолчанию открыт **текущий месяц** — это месячный цикл зарплаты, и цифры сверху читаются как итоги месяца.
- Период — один контрол: стрелки месяца и, на вкладках-списках, переключатель **«Всё время»**. Во включённом режиме месяц не действует и его стрелки погашены. Поэтому выпадающие фильтры стоят сразу после периода на всех вкладках — как на «ФОТ».
- Поиск по ФИО ищет в выбранном периоде. Если ничего не нашлось, пустой экран предлагает «Искать за всё время» — период не меняется молча.
- Если за месяц записей нет, пустой экран тоже предлагает «Показать за всё время». Это важно: премии, например, начисляют не каждый месяц.

| Вкладка | Показатели |
| --- | --- |
| ФОТ | К выплате · Выплачено · Остаток · Баланс |
| Премии | Сумма · Записей · Сотрудников |
| Удержания | Сумма · Записей · Сотрудников |
| Выплаты | Выплачено · Зарплата · Авансы · Записей |

## Как считаются цифры

Считает сервер — те же функции, что и в приложении. Веб ничего не пересчитывает сам.

- **Начисления месяца** — `calculate_payroll_for_month`: часы только из закрытых смен и ручного табеля, ставка подбирается на дату смены, суточные — по объекту, премии и удержания — за месяц. «К выплате» = база + суточные + премии − удержания. Выплаты в эту сумму не входят.
- **Выплаты, остаток, баланс на вкладке ФОТ** — распределение FIFO: выплата гасит сначала долг прошлых лет, затем месяцы года по порядку. Если гасить нечего, остаток относится на календарный месяц выплаты. Считается в браузере тем же способом, что в приложении и в Excel-выгрузке.
- **Вкладка «Выплаты» — это факт**, а не FIFO: суммы по дате выплаты. Поэтому цифра «Выплачено» на вкладке «Выплаты» и колонка «Выплаты» на вкладке «ФОТ» — разные числа, и это правильно.
- **Состав строк ФОТ.** При «Все объекты» в таблицу попадают и сотрудники без начислений за месяц — если они в штате и устроены не позже конца месяца либо имеют ненулевой баланс. При выбранном объекте — только строки с активностью на этом объекте.
- **Объект и баланс.** У выплат нет объекта, поэтому при выбранном объекте начисления показываются по объекту, а «Выплаты», «Остаток» и «Баланс» — по компании целиком. Это как в приложении.

## Экспорт в Excel

Кнопка «Excel» — в панели фильтров справа. Файл собирается **в браузере** (`exceljs`), серверные функции не используются. Нужно право `payroll.export`; без него кнопки нет.

Выгружается активная вкладка с текущими фильтрами — то, что видно на экране:

| Вкладка | Файл | Колонки |
| --- | --- | --- |
| ФОТ | `ФОТ_Сентябрь_2026.xlsx` | Сотрудник · Статус · Часы · Ставка · База · Премии · Удержания · Суточные · К выплате · Выплаты · Остаток · Баланс |
| Премии | `Премии_Сентябрь_2026.xlsx` | Дата · Сотрудник · Сумма · Объект · Примечание |
| Удержания | `Удержания_Сентябрь_2026.xlsx` | то же, сумма со знаком минус |
| Выплаты | `Выплаты_Сентябрь_2026.xlsx` | Дата · Сотрудник · Сумма · Способ · Тип · Комментарий |

- В файле есть шапка (название, период, дата формирования), строка «ИТОГО», закреплённая шапка таблицы и автофильтр по колонкам.
- **Формулы для расчёта.** В ведомости «К выплате» = База + Суточные + Премии − Удержания, «Остаток» = К выплате − Выплаты. Строка «ИТОГО» — суммы по колонкам. Правите премию или удержание — итоги пересчитываются сами.
- «База» и «Баланс» остаются числами: база считается по ставке на дату каждой смены (из «Часы × Ставка» не выводится), а баланс — накопленный итог по всей истории, в месячном листе его не из чего сложить.
- Даты — настоящие даты Excel (можно сортировать и фильтровать), суммы — числа с форматом `#,##0.00 ₽`.
- Уволенные в ведомости подсвечены розовым, как в приложении.
- Порядок строк — как на экране, с учётом сортировки по клику на заголовок.
- Если строк нет, выгрузка не запускается: появляется предупреждение.

## Доступ

| Действие | Право |
| --- | --- |
| Открыть раздел | `payroll.read` |
| Создать премию, удержание или выплату | `payroll.create` |
| Изменить запись | `payroll.update` |
| Удалить запись | `payroll.delete` |
| Карточка сотрудника по ФИО | `employees.read` |
| Выгрузка в Excel | `payroll.export` |

Без права просмотра пункт «ФОТ» в меню скрыт, а адрес `/payrolls` показывает «Доступ запрещён».

Имена сотрудников в списках приходят связанной записью `employees` — то есть нужен ещё и доступ к справочнику сотрудников (право `employees.read` есть у всех ролей с доступом к ФОТ).

Права проверяются и на экране, и в базе (RLS на `payroll_bonus` / `payroll_penalty` / `payroll_payout`): запись — по `payroll.create` / `update` / `delete`. На чтение `payroll.read` видит всю компанию, а сотрудник без этого права — только свои строки (это нужно для экрана «Финансовая информация» в приложении).

## База

Читаются таблицы `payroll_payout`, `payroll_bonus`, `payroll_penalty`, `employee_rates`, `business_trip_rates`, `work_hours`, `works`, `employee_attendance`, `employees`, `objects`.

Вызываются функции:

- `calculate_payroll_for_month` — ведомость месяца (и 12 раз для FIFO);
- `calculate_employee_balances_before_date` — долг до начала года;
- `get_employee_payroll_totals` — итоги по сотруднику за всё время (база, суточные, премии, удержания, выплаты, начислено, остаток) для окна истории.

Запись операций идёт напрямую в таблицы: `payroll_bonus` / `payroll_penalty` (insert, update, delete) и `payroll_payout` (insert, update, delete). Массовые операции и импорт пишутся **одной вставкой массивом** (атомарно). Разбор Excel делает Node-роут, запись — из браузера (права и аудит). Поля: `company_id`, `employee_id`, `object_id` (у выплаты нет), `date` / `payout_date`, `amount`, `reason` / `comment`, `type = 'manual'` (у выплаты — выбранный тип), `id` генерируется на клиенте. Удаление — по `id` и `company_id`.

**Аудит.** Миграция `payroll_operations_audit` добавила в эти таблицы `created_by` / `updated_by` (ссылка на `profiles`) и `updated_at`; триггер заполняет их из `auth.uid()`. Старые строки остаются без автора.

**Права в базе.** Миграция `payroll_operations_rls` заменила прежние политики «любой участник компании» на проверку `payroll.*` с исключением «сотрудник видит свои строки» (см. «Доступ»).

Длинные списки грузятся порциями по 1000 строк (лимит PostgREST): выплат за всё время 1171 строка — это две порции.
