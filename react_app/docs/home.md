# Главная

**Дата:** 13.09.2026  
**Экран:** `/` — `HomePage`: ширина **&lt; 768px** → `HomeMobile`, иначе `HomeDesktop`.  
**Телефон:** раздел доступен в меню и по адресу (вместе с [ГТ Диском](./gt-disk.md), [Сотрудниками](./employees.md), [Работами](./works.md) и [Профилем](./profile.md)). Шапка сайта скрыта, своя мобильная шапка.  
**После входа:** и телефон, и компьютер открывают эту страницу (у нового пользователя — после завершения профиля и выбора организации, [auth.md](./auth.md)).  
**Данные:** смены текущего месяца (`works`), часы (`work_hours`), объекты, сотрудники и договоры — по правам просмотра. Норма выработки — `companies.min_output_per_person_hour`. Flutter этим экраном не управляется.

## Что умеет

Один набор цифр для компьютера и телефона (`useHomeDashboard`). Внешний вид разный.

- Приветствие, компания, роль, дата
- Карточки показателей
- График выработки и явки за месяц
- Смены сегодня; на компьютере ещё активные объекты и последние смены
- На компьютере блок **«Требуют действия»**: сколько заявок ждёт согласования и оплаты (если есть право «просмотр» раздела заявок). По нажатию — переход в раздел заявок
- Переходы в разделы, на которые есть право «просмотр»
- Кнопка «Открыть смену» при праве `works.create`. Если у пользователя уже есть открытая смена — предупреждение и переход в журнал смен

Без права на работы график и список смен пустые. Сотрудники и договоры без права показывают «—».

## Показатели

| Карточка | Смысл |
| --- | --- |
| Смены сегодня | Сколько **открытых** смен на сегодня |
| Объекты в работе | Статус «активный» среди объектов в зоне доступа (профиль, либо все — у владельца/супер-админа); рядом всего объектов в этой зоне |
| Персонал в штате | Сотрудники со статусом «работает» (если есть право) |
| Договоры | Действующие договоры (если есть право) |

На телефоне отдельной строкой — сумма выработки сегодня по сменам дня (`totalAmount`).

Явка на карточках и на графике — сумма `employeesCount` по сменам дня, не уникальные люди.

## Заявки на закупку (Требуют действия)

На компьютере в правой колонке — блок по заявкам на закупку (только при праве «просмотр» раздела):

| Строка | Какие статусы заявок |
| --- | --- |
| Требуют согласования | Статус «На согласовании» (`approval`) |
| Требуют оплаты | Статус «Заведено на оплату» (`payment_queue`) |

Счётчики строго соответствуют одноимённым фильтрам в реестре заявок, а клик по строке сразу открывает реестр с предвыбранным фильтром. Пустые строки не показываются; если заявок нет — «Все заявки обработаны». Раздел заявок открывается только на компьютере, поэтому на телефоне блока нет.

## График

Две шкалы:

- сплошная линия — факт выработки в ₽ (сумма `totalAmount` смен дня)
- янтарная — явка (сумма людей по сменам дня)
- пунктир «План» — только если в организации задана норма больше нуля

**План дня** = сумма фактических часов смен этого дня (`work_hours.hours`) × норма ₽ / чел. / час. Пустые часы дают план 0. Норма не считается как «8 часов на человека».

Период по умолчанию: телефон — 14 дней, компьютер — весь месяц. Можно выбрать объект (список shadcn Select) — только объекты из зоны доступа, как у смен.

В подсказке при наведении: факт, план, процент выполнения, часы, число смен.

Норму задаёт владелец в [Профиль → Организация](./profile.md). Пустое поле — пунктира нет.

## Данные

- Смены месяца: тот же запрос, что журнал работ, с учётом объектов профиля
- Объекты на главной (карточка, KPI, фильтр графика): те же, что у смен. Не владелец и не супер-админ — только `profiles.object_ids`, из них «в работе» со статусом «активный». Владелец и супер-админ — все объекты компании.
- Часы для плана: сумма `work_hours.hours` по сменам месяца
- Норма: поле компании активной организации; меняет только владелец (проверка базы: `companies.owner_id`)

Миграция колонки: `20260913100000_companies_min_output_per_person_hour` (в репозитории базы, не в этом сайте).
