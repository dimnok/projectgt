## Что умеет

- **Реестр счетов.** На компьютере — полоса показателей сверху (к оплате, оплачено, остаток, всего счетов), ниже фильтры с поиском, затем таблица во всю ширину: дата, тип, счёт, акт, договор, контрагент, объект, к оплате, статус, оплачено, остаток. Шапка таблицы закреплена при прокрутке; по клику на заголовок — сортировка (первый клик — нужное направление, второй — обратное, третий — исходный порядок). Внизу — постраничная навигация (по 50 счетов). На телефоне — карточки с кнопкой «Показать ещё», внизу — итоги: к оплате, оплачено, остаток
- **Поиск** по номеру счёта, номеру акта, примечанию, договору, контрагенту и объекту — идёт на сервер, а не по загруженной странице
- **Фильтры:** тип (акт / аванс / прочее), статус оплаты (не оплачен / частично / оплачен / переплата), контрагент, объект, договор. Фильтры, поиск, сортировка и подсчёт итогов выполняются на сервере — каждый экран делает по одному запросу на список и на итоги
- **Создание, правка и удаление счёта.** Объект, контрагент, договор, тип операции, номер акта (для акта), номер и дата счёта, сумма, НДС и примечание
- **НДС:** включение, ставка (22 / 10 / 7 / 5 / 0 %) и режим «НДС в сумме» / «НДС сверху» со сводкой «без НДС / НДС / итого». Ставка **0 % (экспорт) сохраняется** и не превращается в «без НДС»
- **Карточка счёта:** сводка (к оплате / оплачено / остаток / статус), реквизиты, документы и оплаты. Клик по строке или карточке открывает счёт
- **Оплаты:** добавить, изменить, удалить. Статус и суммы счёта база пересчитывает автоматически
- **Оплаты из банковской выписки** (из модуля ДДС) в веб-карточке показываются, но не редактируются и не удаляются — меняются только транзакцией в ДДС
- **Документы счёта:** прикрепить, открыть (просмотр внутри приложения), скачать, удалить. Файлы лежат в приватном хранилище `settlement_files`. Принимаются PDF, Word, Excel и изображения до 20 МБ
- **PDF счёта** кнопкой «Сформировать PDF». Формирует серверный роут (`/api/settlements/invoice-pdf`) и открывает документ на просмотр внутри приложения; при наличии права «изменение» PDF сохраняется в документы счёта (перезаписывая предыдущую автоверсию)
- **Вкладка «Финансы» в договоре:** счета по договору, показатели «к оплате / оплачено / долг», таблица и кнопка «Новый счёт» с предзаполненным договором

## На телефоне

Логика та же, что на компьютере: те же данные, права и действия. Отличается подача.

- Шапка: название раздела и кнопка «+» для нового счёта (если есть право). Общая шапка сайта на телефоне скрыта — она не дублируется
- Поиск и лента фильтров по статусу оплаты над списком
- Реестр — карточки; внизу — итоги. «Показать ещё» догружает следующую порцию, уже показанные строки не перечитываются
- Клик по карточке открывает счёт на весь экран: сводка, реквизиты, документы, оплаты и кнопки внизу
- Окна снизу: создание и правка счёта, добавление и правка оплаты, просмотр документа (на весь экран)
- В форме счёта реквизиты свёрнуты в строку-сводку с кнопкой «Изменить», поля разбиты на разделы, номер и дата счёта идут в две колонки
- Кнопка сохранения неактивна, пока не заполнены обязательные поля

## Правила

- Сумма «к оплате», «оплачено» и статус считает **база** (триггеры). Из веба они не отправляются
- Номер счёта подсказывает база (`get_next_settlement_invoice_number`): максимум завершающей цифровой группы + 1 с сохранением префикса
- Номер счёта не может повторяться по одному договору — это гарантирует база (уникальный индекс), поэтому дубль невозможен даже при одновременном сохранении с двух устройств. Сайт показывает понятный текст ошибки, приложение (Flutter) — пока технический
- Пустой номер в уникальность не входит: индекс частичный, правило совпадает с формой, которая требует заполнить номер
- Данные реестра обновляются при возврате на вкладку — оплаты могли измениться в модуле ДДС
- Итоги и страница реестра считаются в базе функциями `get_settlements_summary` и `get_settlements_page` (миграция `20260920140000_settlement_list_rpc.sql`). Итоги читаются даже для пустой страницы — иначе навигация по страницам пропадала бы, если список стал короче
- Права модуля `settlements`: просмотр, создание, изменение, удаление. Изменение нужно для операций с оплатами и документами
- К счёту типа «аванс» или «прочее» удержания не применяются
- Подписи статуса оплаты и типа операции берутся из справочников (`utils/payment-status.ts`, `utils/operation-type.ts`) — в экранах они не дублируются
- Кнопка сохранения в мобильном окне активна только когда форма заполнена целиком (проверка та же, что при сохранении)
