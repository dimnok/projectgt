# Роли и права

**Дата:** 10.09.2026  
**Экран:** `/roles` — только компьютер. На телефоне раздел в меню не показывается.  
**Данные:** `roles`, `role_permissions`, `app_modules`, `company_members`. Та же база, что у рабочего приложения. Приложение (Flutter) не менялось.

Веб больше не открывает все разделы всем, кто вошёл. Кнопки и меню смотрят те же права, что и база: функция `check_permission`.

## Как считается доступ

- Владелец компании (`company_members.is_owner`) — все права.
- Остальные — галочки своей роли. Поле `system_role = admin` само по себе ничего не открывает.
- В базе действие просмотра называется `read`, не `view`.
- Журнал работ в базе — модуль `export`.

Без роли и не владелец: после входа открывается только профиль, пока руководитель не назначит роль.

## Экран «Управление ролями»

Слева — права выбранной роли. Справа — список ролей, создание, сохранение и удаление.

- Системную роль «Супер-админ» можно смотреть, менять нельзя.
- В матрице только действия модуля, без пустых колонок.
- Название роли в базе уникально на всю систему: вторую роль «Админ» создать нельзя.

Права: `roles.read` / `create` / `update` / `delete`.

## Пользователи

Владелец может назначить роль в списке пользователей. База разрешает смену `company_members.role_id` только владельцу.

Привязка карточки сотрудника по-прежнему по праву `users.update`.

## Меню

Пункт виден при праве `read` на модуль. Нет права — пункта нет. Зашли по адресу без права — «Доступ запрещён». Неперенесённые разделы с правом `read` остаются бледными («пока в приложении»).
